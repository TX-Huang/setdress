# 擦掉照片裡的東西

> 2026-11-21 · 使用者：「上傳家裡的圖，我可以點選圖片物件刪除，這樣可以把雜物清除掉」

## 要做的事

上傳自己家的照片後，點一下照片上的東西（雜物、舊家具），AI 圈出它，按「擦掉」就把它從照片上補成後面的牆或地板。
擦乾淨之後，再把燈、地毯放進去看。

## 驗收句子

1. 照片右上角有「擦掉」工具（在量尺旁邊）。打開後點照片上的東西：AI 圈出那個東西，用半透明紅色標出來
2. 再點同一個東西沒圈到的地方：加進同一個範圍；大的東西（沙發、上面堆了衣服抱枕）可以在照片上拖一個框，框裡的整個東西一次圈起來（MobileSAM 的框提示）。
   按鈕列放在照片下面，不蓋住照片（2026-11-22 使用者回報擦不掉沙發：手機上按鈕列蓋住照片上面三分之一，點不到被蓋住的東西）
3. 按「擦掉」：圈起來的範圍往外多擴一點（把邊緣和緊貼的影子一起補），補成後面的牆、地板；範圍外的像素完全不變
4. 擦掉的地方不再擋住新放的商品：那一塊的遮擋深度變成 0（地板、天花板本來就是 0）
5. 「復原」回到上一步；「全部還原」回到原本的照片和遮擋。最多記 8 步（含原本；一步要存一整張照片，太多手機會不夠記憶體），超過就丟掉最舊的中間步，原本的一定留著
6. 擦掉的時候，照片只在這台電腦的瀏覽器裡處理，不送到任何地方；從本機服務（127.0.0.1）打開也一樣用瀏覽器算。（AI 對齊在本機服務模式會把照片送到同一台電腦的服務，那是原本就有的，照片也沒有離開這台電腦）
   擦到一半上傳了新照片：舊照片的結果丟掉，不會貼到新照片上
7. 模型第一次用才下載：圈物件用 MobileSAM（44 MB，Apache-2.0；轉成 ONNX 的版本是 MIT），補圖用 MI-GAN（28 MB，MIT）；授權檔放在 `prototype/models/`。下載完存在瀏覽器裡，下次不用再抓；下載時顯示進度
8. 換一張照片：圈的範圍（紅色）、擦掉的紀錄、按鈕狀態馬上清掉
9. 量尺和擦掉同時只能開一個；擦掉開著時，點照片不會拖到商品

## 結果（2026-11-21）

**先用 Python 試模型的用法**（說明文件沒寫清楚的，實際跑出來）：
- MI-GAN 的遮罩：0 是要補的、255 是保留的。反過來的話什麼都不會補
- MobileSAM 的輸入：直接給 0 到 255 的原始像素（模型自己正規化）。先正規化的話，圈出來跟商品去背的重疊只有 59%；原始的是 95%

**一張實景照（店家的商品照，只在本機）**：
- 點落地燈的燈罩和燈桿：整盞燈不見，後面的窗戶、暖氣片補得很自然
- 點盆栽的盆子：只圈到盆子，葉子要再點一下才會圈到（所以有「再點一下加進範圍」）
- 沒有顯示卡（CPU）：圈物件約 0.2 秒、補圖約 0.2 秒

**在網頁上實際操作（示範房間）**：
- 按「擦掉」→ 點盆栽的葉子（圈到葉子）→ 再點盆子（加進範圍）→ 按「擦掉」：盆栽不見，牆和地板補乾淨
- 牆上的影子沒被圈到（跟第 3 句說的一樣）；點影子再擦一次，也乾淨了
- 「復原」影子回來，「全部還原」盆栽回來；按鈕在原本的照片上會關掉
- 假的 AI 深度（整張 3 m）、擦掉左上角四分之一：遮擋深度剛好 300／1200 格變成 0；復原後全部回來
- 量尺和擦掉只能開一個；換一張照片，擦掉的紀錄清掉
- 網路紀錄：只有第一次下載三個模型（都存進瀏覽器，大小跟原檔一樣），沒有任何上傳
- 接上真的 AI 深度（瀏覽器版 MoGe 對齊示範房間）：盆栽那一點的深度本來 4.67 m，擦掉後變成 0
- 原本的 AI 對齊沒有被改壞（下載模型的程式改成可以下載別的模型）：對齊示範房間，鏡頭高 1.29 m、天花板 2.73 m（正確 1.35、2.7），跟以前一樣
- 點錯地方的樣子：點到牆，AI 會圈整面牆；這時按「重選」就好（按了「擦掉」也可以「復原」）
- 測試：`erase.js` 14 個（JS 共 116 個）；網站白名單、本機服務也有測試。故意把 `erase.js` 改壞 17 種，每一種都有測試抓到

**Codex 審查**（5 點）：4 點是真的、都修了；1 點是文件寫得不清楚
- 擦到一半上傳新照片，舊照片的結果會貼到新照片上 → 算完先確認還是同一張照片。在網頁上實測：2048 px 的照片擦到一半換成 800 px 的，最後是新照片、紀錄 1 步；把這個修正拿掉再跑一次，舊的結果真的會貼上去（所以這個測法抓得到）
- 換照片時紅色範圍、按鈕沒有馬上清掉 → 換照片就清（網頁上實測）
- 擦很多次會一直存整張照片 → 最多記 8 步（有測試）
- 存在瀏覽器裡的模型壞掉會一直打不開 → 打不開就丟掉、重新下載一次
- 「本機服務模式會把照片送出去」：那是原本就有的 AI 對齊，送到同一台電腦的服務；擦掉本身不送。第 6 句改寫清楚

## 業界怎麼做、我們怎麼超越

### 業界

- **IKEA Kreativ**：網頁上點有黃色外框的家具，它就消失；「Hide All」一次全清（[說明頁](https://www.ikea.com/ca/en/customer-service/knowledge/articles/g81237dc-557d-4d2e-b0fd-24c6d8e46705.html)）。
  背後是 Geomagical 的論文：先找出家具、把牆和地板拉正，再用重新訓練過的 LaMa 補（[arXiv 2210.15796](https://arxiv.org/abs/2210.15796)）；
  專利寫擦掉的地方深度用後面的平面內插，或設成無限遠讓它永遠不擋新商品（[US11727587](https://patents.google.com/patent/US11727587B2/en)）。
  照片要上傳到 IKEA 的伺服器處理（[`research-ikea-kreativ.md`](research-ikea-kreativ.md)）
- **點一下選物件**：Segment Anything（SAM）系列是標準做法；MobileSAM 是能在手機、瀏覽器跑的小版本（[GitHub](https://github.com/ChaoningZhang/MobileSAM)）
- **補圖**：LaMa（[GitHub](https://github.com/advimman/lama)，208 MB）是最常用的開源模型；MI-GAN 是給手機用的小模型（[GitHub](https://github.com/Picsart-AI-Research/MI-GAN)，28 MB）
- **商用 API**：例如 Bria Eraser，每張約 US$0.04，照片要上傳

### 我們的

- **照片不離開這台電腦**：圈物件和補圖都在瀏覽器裡跑。IKEA、商用 API 都要上傳照片。量法：擦掉的時候看網路紀錄，除了第一次下載模型，沒有任何請求
- **點什麼都可以擦**（就我所知是新的）：IKEA 只能擦它認得的家具（有黃框的）；我們用 SAM 點選，桌上的雜物、牆上的東西也可以
- **擦掉的地方深度設成 0**：照專利寫的「設成無限遠」那個做法，不說超越
- **補得比 IKEA 差**：我們用 28 MB 的小模型、沒有把牆和地板拉正；大塊的、有花紋的地方會糊。這一點比業界差

### 不做的

- **LaMa**：補得比較好，但 208 MB，網頁太重。之後可以在本機服務用 LaMa、網頁用 MI-GAN
- **把牆和地板拉正再補**（Geomagical 的做法）：要先有牆的平面，現在只有地板和天花板。下一步
- **自動找出所有家具、一鍵全清**：要另一個偵測模型，先做點選
- **清影子**：影子不在圈的範圍裡就不會被擦；先用「往外多擴一點」處理緊貼的影子
