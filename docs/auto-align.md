# AI 自動對齊

> 2026-11-19 · 對應 [MVP 規格](mvp-spec.md) 的「第 1 步」和「對齊」驗收句子

## 要做的事

使用者上傳一張房間照片。我們算出 5 個數字，自動把原型裡「對齊照片」的滑桿設好：

| 數字 | 原型裡的滑桿 |
|---|---|
| 鏡頭離地（公尺） | 鏡頭離地 |
| 往下看的角度（度，往下是正的） | 往下看的角度 |
| 歪斜（度） | 歪斜 |
| 垂直視角（度） | 視角 |
| 天花板高度（公尺；看不到天花板就是「不知道」） | 天花板高度 |

## 做法

分成兩半。**第二半跟用哪個 AI 模型無關**，所以先做。

1. **AI 深度模型**（之後挑）：照片 → 每個像素在鏡頭前面的 3D 位置（公尺）+ 鏡頭焦距
2. **幾何計算**（`tools/autoalign/geometry.py`）：
   1. 照片下半部的點，用 RANSAC（隨機抽點、找最多點落在上面的平面）找出「水平面」，得到「往上」的方向
   2. 只看平躺的表面，沿著「往上」的方向看每個點有多低。最低、而且至少佔照片下半部 3% 的那一層就是地板。這樣桌面、沙發座墊、蓋住大半地板的床都不會被當成地板
   3. 鏡頭離地 = 鏡頭到地板的距離。如果最大的水平面是床面，就讓床面和地板一起決定「往上」的方向（兩個面是平行的），只露出一小條地板時角度才不會歪
   4. 往下看的角度、歪斜 = 「往上」的方向在鏡頭裡偏了多少
   5. 照片上半部、比鏡頭高、**表面朝下**、點又夠多的那一層 = 天花板（用表面朝向分牆和天花板：牆是直立的，天花板是平躺的）
   6. 垂直視角 = 從焦距算

## 驗收句子

### 幾何計算（用電腦做出來的假房間測，答案已知）

- 乾淨的房間：鏡頭離地誤差 ≤ 1 cm，角度誤差 ≤ 0.5°，視角誤差 ≤ 0.5°，天花板誤差 ≤ 2 cm
- 鏡頭往下 25°、歪 4°：一樣在上面的誤差內
- 深度有 2% 雜訊：鏡頭離地和天花板誤差 ≤ 5%（規格要求 ≤ 10%，留一倍空間）
- 30% 的點是壞的（沒有深度）：結果一樣在誤差內
- 地板上有桌子和沙發：還是找到真的地板，不會把桌面當地板
- 床或地上的床墊蓋住大半地板，只露出一小條（約佔下半部 4%，跟真照片一樣）：還是找到真的地板，不會把床面當地板
- 照片裡看不到天花板：天花板回傳「不知道」，不亂猜
- 照片裡看不到地板：回報錯誤「看不到地板」，不亂猜
- 輸入的形狀不對：回報錯誤

### 真的照片（第 1 步）

- 10 張真實房間照片，每張用捲尺量好實際天花板高度
- 天花板高度誤差 ≤ 10%
- 把算出來的格線畫在照片上，人眼看：10 張至少 8 張貼齊地板
- 一張照片處理 ≤ 10 秒（在有顯示卡的電腦上）
- 照片處理完就刪

### 接進原型（本機對齊服務 `server.py`）

- 原型上傳照片後，把照片送到這台電腦上的對齊服務；10 秒內 5 個滑桿自動設好，格線畫在地板上
- 看得到地板、看不到天花板：前 4 個滑桿設好，天花板維持原本的值，並提示「天花板沒拍到」
- 看不到地板：滑桿不動，提示「AI 找不到地板，請用滑桿手動對齊」
- 沒開對齊服務（直接打開 HTML，或 claude.ai 上的版本）：跟以前一樣手動對齊，不跳錯誤；而且**照片不會送出去**：只有網頁是從 127.0.0.1 或 localhost 打開的才送
- 服務只接受照片：不是照片回「只支援照片」，超過 20 MB 回「照片太大」，大小亂寫（-1、abc）回「照片大小不對」
- 上傳到一半不送完，10 秒後斷線，不會卡住整個服務
- 照片只在記憶體裡處理，不寫進硬碟；服務只聽 127.0.0.1，別台電腦連不到
- 自動對齊後還能用滑桿微調；「重設對齊」回到 AI 算的值
- 又上傳一張新照片時，舊照片晚到的結果不能蓋掉新的（從選照片那一刻就算，照片解碼慢也一樣）

### 遮擋（家具擋住商品）

對齊服務順便回傳一張「深度圖」：每個像素離鏡頭多遠。原型把它寫進 3D 的深度緩衝區，所以：

- 商品被家具擋住的部分不畫：地毯放到桌子底下，桌腳和椅子畫在地毯前面
- 地板和天花板不擋東西：地毯貼地、吊燈貼天花板都不會被切掉
- 格線被牆或家具擋住的部分不畫
- 深度本來就有誤差：離鏡頭遠 3% + 5 cm 以內不算被擋，商品才不會在貼著家具的地方被亂切
- 沒有深度圖時（沒開服務、示範房間）不遮擋，跟以前一樣；換新照片時，舊照片的遮擋立刻拿掉

## 怎麼跑

在 `tools/autoalign/` 底下：

1. 照片放進 `photos/`（JPG、PNG、WebP）
2. 天花板實量值寫在 `photos/ceilings.csv`（公尺）。`*` 那行套用到沒有單獨寫的照片：

   ```
   photo,ceiling_m
   *,2.8
   bedroom.jpg,2.65
   ```

3. 執行：`.venv/Scripts/python.exe evaluate.py`
4. 看結果：`out/summary.md`（誤差表）、`out/<模型>/`（畫了格線的照片，被牆或家具擋住的格線不畫）

### 用原型試（自動對齊 + 遮擋）

1. 在 `tools/autoalign/` 底下執行：`.venv/Scripts/python.exe server.py`
2. 看到「對齊服務開好了」後，打開 http://127.0.0.1:5191
3. 按「上傳你家照片」：大約 1 秒後格線自動對好，家具會擋住地毯和燈

預設用小版：顯示卡被別的 AI 程式佔住時，大版會載不起來（2026-11-19 就遇到過）。要用大版加 `--model moge-2-l`。

服務只給 `prototype/` 裡白名單上的檔案：`index.html`、`lamps.js`（燈具目錄，見 [lamps.md](lamps.md)）。其他檔案一律「找不到」。

模型：MoGe-2 小版 `moge-2-s`（141 MB）、大版 `moge-2-l`（1.3 GB），都是 MIT 授權。執行環境在 `.venv`，只裝跑 MoGe-2 需要的套件，重用電腦上原本的 PyTorch（CUDA 12.8）。

## 目前結果

### 示範房間（2026-11-19，電腦畫的，答案已知）

| | 鏡頭離地 | 往下看 | 視角 | 天花板 | 每張 |
|---|---|---|---|---|---|
| 正確答案 | 1.35 m | 10° | 55° | 2.70 m | |
| 小版 | 1.24 m | 8.7° | 55.2° | 2.68 m（誤差 0.9%） | 0.3 秒 |
| 大版 | 1.11 m | 9.6° | 61.4° | 2.45 m（誤差 9.4%） | 0.3 秒 |

- 天花板高度兩個都在 10% 內，速度遠低於 10 秒
- 鏡頭離地偏低 8–18%。電腦畫的房間不像真照片，模型估真實尺寸靠的是「真實世界長什麼樣」的經驗，所以這張圖不能代表真照片的表現
- 這次測到一個問題並修好：天花板拍到了，但被「牆比較多」的規則誤判成牆，回傳「不知道」。改成用表面朝向分

### 真實照片（2026-11-19，第一批 4 張）

4 張實拍的室內照片，其中 2 張用捲尺量了天花板高度（照片和實際尺寸不公開）。

| 照片 | 天花板有實量 | 大版誤差 | 小版誤差 | 格線貼齊地板（人眼） |
|---|---|---|---|---|
| A | 有 | 0.1% | 5.3% | 是 |
| B | 有 | 4.4% | 1.7% | 是 |
| C（床墊蓋住大半地板） | 沒有 | | | 是 |
| D（床蓋住大半地板，天花板沒拍到） | 沒有 | | | 是 |

- 有量的 2 張，兩個模型都在 10% 內（大版最大 4.4%，小版最大 5.3%）
- 每張 0.5 秒以內
- **一開始兩張有床的照片都失敗**：床面被當成地板（地板只露出 4.4%，被「至少要有最密那層 25%」的規則丟掉）。已修，見上面「做法」第 2、3 步
- 用照片裡已知大小的東西（流理台、沙發座、茶几、門框）檢查比例尺，都正常
- 天花板有降一階的照片，程式分得出高、低兩段（低的那段誤差 2.4%）
- 拍照的人原本估的天花板高度不準（其中一張差 13%），捲尺量了才知道程式是對的：驗收一定要用捲尺量
- **還不能判斷過不過關**：規格要 10 張有實量的照片，現在只有 2 張

照片處理完的中間檔（深度、診斷圖）沒有留在專案裡；`out/` 有畫格線的圖，不進 git。
