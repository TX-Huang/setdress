# 網頁版 AI 對齊：在瀏覽器裡跑

> 2026-11-20 · 接續 [auto-align.md](auto-align.md)（本機服務版）

## 要做的事

現在 AI 對齊要靠使用者電腦上的 Python 服務和顯示卡。網頁一放上網、或用手機開，就只能手動對齊。

改成：**沒有本機服務時，AI 直接在瀏覽器裡跑**。照片不離開瀏覽器，不用伺服器、不花錢。

## 做法

1. MoGe-2 小版轉成 ONNX（瀏覽器能跑的模型格式），再轉成半精度：141 MB → 71 MB
2. 瀏覽器用 onnxruntime-web 跑：有 WebGPU（用顯示卡）就用，沒有就用 CPU
3. MoGe 的後處理（從模型輸出算焦距、深度、真實尺寸）從 Python 搬到 JS
4. `geometry.py`（找地板、天花板）和 `occlusion.py`（遮擋深度圖）搬到 JS：`prototype/webalign.js`

## 試做結果（2026-11-20）

| | 結果 |
|---|---|
| ONNX 跟 PyTorch 同一張圖的輸出 | 最大差 0.00004 |
| 瀏覽器 WebGPU 跑一次 | 0.25 秒（第一次 2–3 秒暖機） |
| 瀏覽器只用 CPU 跑一次（1200 token） | 約 9 秒 |
| 半精度跟全精度 | 兩張實量照片的天花板一樣（到公分） |

天花板誤差（有實量的 2 張實拍照片；token 越多越細、越慢）：

| | 照片 A | 照片 B |
|---|---|---|
| 現在的本機服務（PyTorch，3600） | 5.3% | 1.7% |
| ONNX 3600 | 5.0% | 1.6% |
| ONNX 2400 | 1.7% | 0.8% |
| ONNX 1800 | 4.7% | 0.8% |
| ONNX 1200 | 9.0% | 4.8% |

所以：有 WebGPU 用 **2400**，只有 CPU 用 **1200**（都在規格的 10% 內；只有 2 張照片，還不能說哪個最好）。

## 驗收句子

### 後處理（MoGe 的 infer）

- 用已知焦距和深度位移做出來的模型輸出，算回來的焦距、位移誤差 ≤ 0.5%
- 同一份模型輸出，JS 算出的點跟 Python（MoGe 原本的程式）比：鏡頭離地差 ≤ 1 cm、角度 ≤ 0.5°、天花板 ≤ 2 cm
- 模型說「沒有深度」的點、深度 ≤ 0 的點都當成沒有深度

### 找地板、天花板（geometry.py 搬到 JS）

跟 [auto-align.md](auto-align.md)「幾何計算」那段一樣的驗收句子，用同一個假房間（也搬到 JS）：

- 乾淨的房間：鏡頭離地誤差 ≤ 1 cm，角度 ≤ 0.5°，視角 ≤ 0.5°，天花板 ≤ 2 cm
- 鏡頭往下 15°、歪 −4° 或 5°：一樣
- 深度有 2% 雜訊：鏡頭離地、天花板 ≤ 5%；角度 ≤ 2°
- 30% 的點是壞的：一樣在誤差內
- 地板上有桌子和沙發、很大很低的平台：還是找到真的地板
- 床或地上的床墊蓋住大半地板：還是找到真的地板；深度一大片一大片偏 3% 時，鏡頭離地 ≤ 5%
- 看不到天花板、只看到比鏡頭高的牆：天花板回傳「不知道」
- 天花板有拍到但深度一大片一大片偏 3%：還是找得到，誤差 ≤ 5%
- 看不到地板：回報「看不到地板」
- 輸入形狀不對、焦距 ≤ 0：回報錯誤
- 同一份點，JS 跟 Python 的結果：鏡頭離地差 ≤ 1 cm、角度 ≤ 0.5°、天花板 ≤ 2 cm

### 遮擋深度圖（occlusion.py 搬到 JS）

- 跟 Python 版一樣的規則：地板、天花板、沒有深度的點是 0；家具是它的距離（公釐）；最長邊縮到 512

### 網頁

- 從這台電腦的對齊服務打開（127.0.0.1／localhost）：照舊用服務
- 其他地方（放上網、claude.ai、手機）：在瀏覽器裡跑；照片不會出現在任何網路請求裡
- 第一次要下載模型（71 MB）：先問「要下載嗎？」，按了才下載，畫面顯示下載進度；下載過的存在瀏覽器裡，下次直接用
- 有 WebGPU：2400 token，10 秒內出結果（有顯示卡的電腦）。沒有：1200 token，先提示「這台裝置比較慢，大約要 10–30 秒」
- 結果跟本機服務一樣：5 個滑桿、天花板沒拍到的提示、找不到地板的提示、遮擋
- 又換了照片時，舊照片晚到的結果不能蓋掉新的
- 模型載入失敗或跑到一半出錯：顯示錯誤，退回手動對齊，網頁不會壞

## 怎麼試

1. 做模型（只要一次）：在 `tools/autoalign/` 底下 `.venv/Scripts/python.exe export_onnx.py` → `prototype/models/moge-2-s-fp16.onnx`（不進 git）
2. 開本機服務 `.venv/Scripts/python.exe server.py`，打開 http://127.0.0.1:5191/?ai=browser （`?ai=browser`：服務有開也強制用瀏覽器版，測試用）
3. 上傳照片 → 第一次會問要不要下載模型 → 按「下載並對齊」

測試：`prototype/` 底下 `node --test`；Python 的對照答案用 `make_web_fixtures.py` 重新產生。

## 目前結果（2026-11-20）

- JS 測試 73 個（燈具 25、網頁版對齊 48）、Python 測試 82 個全過；ruff 乾淨。JS 沒有 lint 設定，只做語法檢查
- 故意把 JS 改壞 15 種，13 種被測試抓到。抓不到的 2 種：「傾斜的表面也算平躺」「不做逐步收緊」——Python 的測試也抓不到，這兩條規則是為真照片的雜訊設的，假房間測不出來
- 為了讓測試抓得到，假房間多了兩個場景（Python、JS 都加）：天花板降一階（回傳高的那段）、廚房吊櫃底面只比鏡頭高 15 cm（不是天花板）
- 在瀏覽器裡實際跑實拍照片（天花板誤差，照片 A、B 同上表）：

| | 瀏覽器版（顯示卡，2400） | 瀏覽器版（只用 CPU，1200） | 本機服務 |
|---|---|---|---|
| 照片 B | 0.9% | | 1.1% |
| 照片 A | 0.6% | 8% | 5.3% |
| 從選照片到對齊好 | 0.5 秒（模型已載入） | 9 秒 | 約 0.5 秒 |

- 只用 CPU 的 8% 還在規格的 10% 內，但很接近；手機多半只能用 CPU
- 第一次問要不要下載、按了才下載、確定能用才存在瀏覽器裡；重開網頁不再問、不再下載
- 從頭到尾沒有任何網路請求帶照片（看過瀏覽器的網路紀錄）；本機服務只送到同一個網站、不跟著轉址
- 遮擋一樣有效：茶几、電風扇畫在地毯前面
- 網站上沒有模型檔（例如 claude.ai）：不問、直接手動對齊

### 換別家公司的模型審（Codex，2026-11-20）

找到 19 點。修了 18 點，每點都先寫會失敗的測試（能測的）或在瀏覽器裡實際試：

- 數學（JS 測試）：解焦距和深度位移改成跟 scipy 一樣用殘差的 LM，並對暴力搜尋檢查；一個沒被遮掉的 NaN 點不會再讓整張照片算不出來；尺寸倍數不對會報錯；遮擋圖縮小時不會讀到照片外面（**Python 原版也有這個 bug，一起修了**）；四捨五入跟 Python 一樣取偶數；分層遇到極端數值不會當掉；「2% 雜訊」的測試原本加錯了（x、y、z 各乘不同倍數），改成沿著視線
- **照片被拉長 1.8%**：原本把照片拉成剛好 token 格子 × 14，長寬比變了、焦距就不對。改成長寬比不變，讓模型自己處理
- 網頁（瀏覽器裡試過）：快速換兩張照片時只問一次、只下載一次，對齊的是後面那張；存壞的模型會被丟掉重新問；顯示卡跑到一半出錯會改用 CPU 再試（故意讓它出錯試過）；請求和下載都有時間上限；下載時先配好記憶體（不再同時有兩份 71 MB）；AI 算出來的數字不合理就不套用
- 伺服器：HEAD 的錯誤回應不帶內容（原始連線測過）
- 模型轉換工具：真的要交出去的半精度檔也要通過比對（最大差 0.012），遇到 NaN 一定失敗
- 沒修：JS 和 Python 的亂數不同，同一個種子抽到的點不一樣。對照測試用的是乾淨的假房間，不受影響

還沒驗證的：

- 沒在真的手機上試過（只在電腦上用 CPU 模擬過手機的流程）
- 只有 2 張有實量的照片
- 計算都在主執行緒：算的時候（CPU 版約 9 秒）網頁會卡住，之後可以搬到 Web Worker
