# Setdress MVP 規格（草稿 v0.2）

> 2026-11-19 · 草稿 · 標 ❓ 的地方等你決定
>
> v0.2 改了方向：從「AI 直接把商品畫進照片」改成「**照片當舞台，商品用 3D**」。

## 一句話

拍一張房間照片 → 把想買的燈、地毯的 3D 模型放進照片 → 拖、轉、開關燈、調色溫，馬上看到 → 旁邊列出哪裡買、多少錢、總共多少。

## 為什麼做

想買軟裝的人，心裡有兩個問題：

1. 放我家好不好看？
2. 全部買下來要多少錢、去哪買？

現在沒有一個工具同時回答這兩題：

| 工具 | 好不好看 | 多少錢、哪裡買 |
|---|---|---|
| roomfit.app（擺擺看） | 只管放不放得下 | ✗ |
| lampclub.tw | ✗ | ✓（只有燈） |
| IKEA Kreativ | ✓（但不能放吊燈、不能調燈光） | 只有 IKEA 自己的商品 |
| **Setdress** | ✓ | ✓（跨品牌、跨通路比價） |

## 做法：照片當舞台，商品用 3D

1. **AI 讀照片**：算出鏡頭角度、地板在哪、天花板多高、每個點離鏡頭多遠（深度）
2. **照片當背景**：商品是真的 3D 模型，用 Three.js（網頁用的 3D 引擎）即時畫在照片上
3. **燈光可以控制**：房間亮度、白天／晚上、窗戶光方向；燈本身可以開關、調亮度、調色溫
4. **美化（選用）**：按一下得到更真實的一張圖。AI 只修邊緣和影子，商品的範圍被鎖住，不能改

### 為什麼不讓 AI 直接畫

- AI 可能把商品畫成別的樣子，客人照圖買，收到的不一樣
- 不能控制燈光
- 每張要等、要付錢

### 為什麼不把 Blender 放進網頁

Blender 太大，目前沒有能用的網頁版。網頁上用 Three.js 即時畫；要電影等級的一張圖，再送到伺服器用真的 Blender 算（見「美化」）。

## 這一版不做

- LiDAR 掃描（之後當「進階模式」，**沿用同一套 3D 商品和 Three.js 舞台**，只是把照片換成掃描的房間）
- 硬裝：拆牆、水電、地板、油漆
- 在網站上結帳（只給通路連結）
- App：先做手機瀏覽器能用的網頁
- 精確的「開燈照亮整面牆」：照片裡的牆不是真的 3D，光打在牆上的樣子是估的，一律標「示意」

## 第 0 步：原型 —— 摸摸看感覺對不對

**還沒寫產品程式之前，先用一個小網頁試手感。**

- 一張照片、一塊地毯、一盞燈（吊燈或落地燈），燈光可以調
- 對齊用手動：拉滑桿，讓地板格線貼齊照片的地板（正式版改成 AI 自動）
- 商品是電腦畫的示意模型，不是真的商品
- 價格是假的

**過關**：你用自己家的照片試，覺得「這樣有幫助、不會很出戲」。
**沒過**：記下哪裡出戲（光？影子？大小？），再決定要修哪裡。

## 第 1 步：測 AI 自動讀照片

- 模型：先測 **MoGe-2** 的大版（1.3 GB）和小版（141 MB）。程式和權重都是 MIT 授權，可以商用。小版夠準的話，以後可以直接在瀏覽器裡跑
- 不夠準再加測 Depth Anything 3（Apache 授權的那幾版）
- 不用 Apple Depth Pro：GitHub 和 Hugging Face 上的授權寫法互相衝突
- 10 張真實房間照片，每張都用捲尺量好實際的天花板高度
- 過關 ❓：天花板高度誤差 ≤ 10%，而且 10 張裡至少 8 張的地板格線看起來貼齊
- 做法和驗收句子：[auto-align.md](auto-align.md)。研究依據：[research-ikea-kreativ.md](research-ikea-kreativ.md)

## 使用流程

1. 上傳一張房間照片。上傳前提醒：光線要夠、橫拍、站在牆角、**要拍到地板和天花板**（要放吊燈，所以比 IKEA 嚴格）
2. AI 讀照片（幾秒）。畫面出現淡淡的地板格線；對不準可以手動微調
3. 選類別 → 選商品 → 商品出現在照片中間的地板上
4. 拖曳移動、旋轉；吊燈可以調垂吊高度
5. 調燈光
6. 想加更多商品，就重複 3–5
7. 清單自動算總價
8. 點商品 → 打開通路的商品頁
9. （選用）按「美化」，得到一張更真實的圖

## 驗收句子

每一句都要能測。測過才算完成。

### 上傳

- 接受 JPG、PNG、HEIC；其他格式顯示「只支援照片」
- 照片超過 20 MB 時顯示錯誤，不送去處理

### 對齊

- 上傳後 10 秒內畫出地板格線
- 可以用滑桿微調：鏡頭高度、往下看的角度、視角、歪斜
- 微調後，已經放好的商品跟著新的地板走，不會飄在空中或沉到地板下

### 擺放

- 選商品後，它出現在畫面中央附近的地板上
- 手指拖曳時，商品沿著地板移動
- 商品照真實尺寸畫：直徑 60 cm 的燈，跟 1 公尺格線比，就是 0.6 格寬
- 吊燈可以調離地高度；電線上端固定在天花板，長度跟著變
- 可以旋轉、刪除

### 燈光

- 燈可以開關；開著時燈罩發亮、地板出現光暈
- 亮度調高時，地板光暈變大變亮
- 色溫 2700K–6500K：2700K 偏黃，6500K 偏白
- 「白天／晚上」調到晚上時，照片變暗，燈的效果變明顯
- 商品在地板上有影子；影子方向跟「窗戶光」的方向一致
- 光打到牆上的效果標「示意」

### 美化（選用）

- 美化後，商品範圍內的形狀和顏色跟美化前一樣（逐像素比對，差異上限 ❓）
- 美化失敗時保留原本的畫面，不扣使用次數

### 購物清單與總價

- 每件商品列出：名稱、品牌、尺寸、每個通路的價格和連結
- 預設選「有現貨裡最便宜」的通路；使用者可以改選別家
- 所有通路都缺貨時，預設選最便宜的，並標「目前都缺貨」
- 總價 = 每件商品所選通路的價格 × 數量，全部加起來
- 總價旁邊寫「不含運費、安裝」
- 每個價格都顯示「更新於 YYYY-MM-DD」
- 價格超過 30 天沒更新，顯示成灰色並標「可能已變動」

### 隱私

- 擺放和調燈只在使用者的瀏覽器裡算，照片不用上傳
- 需要 AI 讀照片或美化時，照片處理完就刪，不留在伺服器 ❓
- 存起來的結果，網址帶一串隨機長碼；沒有那個網址就打不開
- 使用者可以一鍵刪掉自己的照片和結果

## 商品資料

### 這一版：先少量 ❓

3D 模型是最花工的地方，所以先做 **20–50 個商品**。

2026-11-20：原型先放了 lampclub.tw 上 14 盞真的燈（7 類各 2 盞，真實尺寸和價格，3D 是照尺寸做的示意形狀）。見 [lamps.md](lamps.md)。

每個商品要有：

| 欄位 | 例子 |
|---|---|
| 名稱、品牌 | |
| 類別 | 吊燈 / 落地燈 / 檯燈 / 地毯 |
| 尺寸（cm） | 直徑 60、高 40 |
| **3D 模型** | GLB 檔 |
| 商品照片 | 給使用者對照用 |
| 通路清單 | 每家：通路名、價格、連結、有沒有現貨、更新日期 |

### 3D 模型從哪來（由易到難）

1. **地毯**：商品圖 + 尺寸 = 一片平面，幾乎不用做
2. **品牌給設計師的 3D 檔**：很多精品燈具品牌有，要一家一家確認能不能商用
3. **AI 從照片做 3D**：細電線、玻璃燈罩、透光材質比較難，要人工檢查
4. **請人建模**：最準、最貴

每個 3D 模型都要跟商品照片並排檢查：形狀、顏色、比例一致才上架。

### 風險：版權

商品照片和 3D 檔都有版權。內部測試先用，**公開上線前一定要解決授權**：拿到同意，或改用合作方提供的檔案。

## 技術

- 網頁，手機瀏覽器優先
- Three.js 畫 3D
- AI 讀照片：在伺服器或瀏覽器跑深度模型（第 1 步決定）
- 美化：AI 改圖，或伺服器跑 Blender 算圖 ❓
- 一個小後端：放 AI 的 API 金鑰，不能放在網頁裡

## 成本

- 擺放、調燈：在使用者手機上算，**不花錢**
- AI 讀照片：每張一次，第 1 步量出多少錢
- 美化：每張要錢，要設上限（例如每人每天幾張），不然會被刷爆
